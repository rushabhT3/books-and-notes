### **📌 DOCKER - BASICS & CONCEPTS** (3 Questions)

#### **Question 1**
What is Docker?

*   A) A shipping company
*   B) A platform for developing, shipping, and running applications in containers
*   C) A virtual machine
*   D) An operating system

**Answer: B**
> **Explanation:** Docker enables packaging applications with dependencies into containers that run consistently across environments. Containers are lightweight, portable, and isolated.

---

#### **Question 2**
What is the difference between a Docker image and container?

*   A) They are identical
*   B) An image is a read-only template; a container is a running instance of an image
*   C) Container is the template
*   D) Image is always running

**Answer: B**
> **Explanation:** 
> - **Image**: Read-only blueprint containing code, runtime, libraries, and dependencies
> - **Container**: Running instance created from an image with a writable layer
> - One image can spawn multiple containers

---

#### **Question 3**
What is a Dockerfile?

*   A) A document file
*   B) A text file containing instructions to build a Docker image
*   C) A configuration file
*   D) A log file

**Answer: B**
> **Explanation:** Dockerfile contains step-by-step instructions for building Docker images:
> ```dockerfile
> FROM python:3.11
> WORKDIR /app
> COPY requirements.txt .
> RUN pip install -r requirements.txt
> COPY . .
> CMD ["python", "app.py"]
> ```

### **📌 DOCKER - DOCKERFILE INSTRUCTIONS** (3 Questions)

#### **Question 4**
What is the difference between CMD and ENTRYPOINT in Dockerfile?

*   A) They are identical
*   B) CMD provides default arguments that can be overridden; ENTRYPOINT specifies the executable that's harder to override
*   C) CMD is deprecated
*   D) ENTRYPOINT is for entry points only

**Answer: B**
> **Explanation:** 
> | Feature | CMD | ENTRYPOINT |
> |---------|-----|------------|
> | Purpose | Default command/args | Main executable |
> | Override | Easily with `docker run` args | Requires `--entrypoint` flag |
> | Combination | Provides args to ENTRYPOINT | Receives args from CMD |
> 
> Best practice: Use ENTRYPOINT for the executable, CMD for default arguments.

---

#### **Question 5**
What is the purpose of .dockerignore file?

*   A) To ignore Docker commands
*   B) To exclude files from the build context, reducing image size and build time
*   C) To ignore containers
*   D) A deprecated feature

**Answer: B**
> **Explanation:** .dockerignore specifies files/directories to exclude from the build context:
> ```
> .git
> node_modules
> *.log
> .env
> __pycache__
> ```
> Benefits: Smaller context, faster builds, prevents secrets from being copied.

---

#### **Question 6**
What is the difference between COPY and ADD in Dockerfile?

*   A) They are identical
*   B) COPY copies local files; ADD also supports URLs and automatic tar extraction (but COPY is preferred)
*   C) ADD is deprecated
*   D) COPY is for directories only

**Answer: B**
> **Explanation:** 
> | Feature | COPY | ADD |
> |---------|------|-----|
> | Local files | ✅ | ✅ |
> | URLs | ❌ | ✅ |
> | Auto-extract tar | ❌ | ✅ |
> | Predictability | More predictable | Can be surprising |
> 
> **Best practice**: Use COPY unless you specifically need ADD's features.

### **📌 DOCKER - STORAGE & NETWORKING** (2 Questions)

#### **Question 7**
What is a Docker volume?

*   A) Sound volume
*   B) A mechanism for persisting data generated by containers, independent of container lifecycle
*   C) Container storage
*   D) Image size

**Answer: B**
> **Explanation:** Docker volumes:
> - Persist data outside containers
> - Survive container removal
> - Can be shared between containers
> - Managed by Docker
> - Types: Named volumes, bind mounts, tmpfs mounts
> ```bash
> docker volume create mydata
> docker run -v mydata:/app/data myimage
> ```

#### **Question 8**
What is a Docker network?

*   A) Internet connection
*   B) A virtual network enabling communication between containers
*   C) Physical network
*   D) A deprecated feature

**Answer: B**
> **Explanation:** Docker network types:
> | Type | Description |

### **📌 DOCKER - COMPOSE & MULTI-STAGE** (2 Questions)

#### **Question 9**
What is Docker Compose?

*   A) Music composition tool
*   B) A tool for defining and running multi-container Docker applications using YAML configuration
*   C) A build tool only
*   D) A deprecated feature

**Answer: B**
> **Explanation:** Docker Compose uses `docker-compose.yml`:
> ```yaml
> version: '3.8'
> services:
>   web:
>     build: .
>     ports:
>       - "8000:8000"
>     depends_on:
>       - db
>   db:
>     image: postgres:15
>     volumes:
>       - pgdata:/var/lib/postgresql/data
> volumes:
>   pgdata:
> ```
> Commands: `docker-compose up`, `docker-compose down`

#### **Question 10**
What is Docker multi-stage build?

*   A) Building in stages
*   B) A technique using multiple FROM statements to create smaller final images by copying only needed artifacts
*   C) A deprecated feature
*   D) Building multiple containers

**Answer: B**
> **Explanation:** Multi-stage builds create smaller production images:
> ```dockerfile
> # Build stage
> FROM node:18 AS builder
> WORKDIR /app
> COPY package*.json ./
> RUN npm install
> COPY . .
> RUN npm run build
> 
> # Production stage
> FROM nginx:alpine
> COPY --from=builder /app/dist /usr/share/nginx/html
> ```
> Result: Final image only contains nginx and built files, not Node.js or node_modules.

### **📌 KUBERNETES - CORE CONCEPTS** (3 Questions)

#### **Question 11**
What is Kubernetes?

*   A) A container
*   B) An open-source container orchestration platform for automating deployment, scaling, and management
*   C) A Docker replacement
*   D) A cloud provider

**Answer: B**
> **Explanation:** Kubernetes (K8s) orchestrates containerized applications:
> - **Automated deployment** and rollbacks
> - **Scaling** (horizontal and vertical)
> - **Self-healing** (restarts failed containers)
> - **Service discovery** and load balancing
> - **Secret and configuration** management
> - **Storage orchestration**

---

#### **Question 12**
What is a Kubernetes Pod?

*   A) A container group
*   B) The smallest deployable unit in Kubernetes, containing one or more containers sharing network and storage
*   C) A node type
*   D) A service type

**Answer: B**
> **Explanation:** Pods are atomic units in Kubernetes:
> - Contain one or more containers
> - Share network namespace (same IP address)
> - Share storage volumes
> - Share lifecycle (created/deleted together)
> - Usually one main container per pod (sidecar pattern for multiple)

---

#### **Question 13**
What is a Kubernetes Namespace?

*   A) A naming convention
*   B) A virtual cluster for partitioning resources, providing isolation and organization
*   C) A physical cluster
*   D) A deprecated feature

**Answer: B**
> **Explanation:** Namespaces partition cluster resources:
> - Logical isolation for multi-team/multi-project
> - Resource quotas per namespace
> - Network policies per namespace
> - Default namespaces: `default`, `kube-system`, `kube-public`, `kube-node-lease`
> ```bash
> kubectl get pods -n my-namespace
> kubectl create namespace my-namespace
> ```

### **📌 KUBERNETES - WORKLOAD CONTROLLERS** (5 Questions)

#### **Question 14**
What is the difference between a Pod and a Deployment?

*   A) They are identical
*   B) Pod is a single instance; Deployment manages multiple Pod replicas with rolling updates and rollbacks
*   C) Deployment is deprecated
*   D) Pod manages Deployments

**Answer: B**
> **Explanation:** 
> | Feature | Pod | Deployment |
> |---------|-----|------------|
> | Unit | Single instance | Manages multiple pods |
> | Self-healing | No | Yes (recreates failed pods) |
> | Scaling | Manual | Declarative replicas |
> | Updates | Delete and recreate | Rolling updates |
> | Rollback | No | Yes |

---

#### **Question 15**
What is a ReplicaSet in Kubernetes?

*   A) A replica database
*   B) A controller ensuring a specified number of Pod replicas are running at any time
*   C) A service type
*   D) A deprecated feature

**Answer: B**
> **Explanation:** ReplicaSets maintain desired Pod count:
> - Ensures specified number of replicas
> - Creates new pods if any fail
> - Typically managed by Deployments (not used directly)
> - Selector identifies which pods it manages
> ```yaml
> spec:
>   replicas: 3
>   selector:
>     matchLabels:
>       app: myapp
> ```

---

#### **Question 16**
What is a StatefulSet?

*   A) A state machine
*   B) A workload controller for stateful applications requiring stable identities, persistent storage, and ordered deployment
*   C) A deprecated feature
*   D) A service type

**Answer: B**
> **Explanation:** StatefulSets for stateful applications:
> | Feature | Deployment | StatefulSet |
> |---------|------------|-------------|
> | Pod names | Random (app-xyz123) | Stable (app-0, app-1) |
> | Storage | Shared | Dedicated PVC per pod |
> | Scaling | Parallel | Ordered (0→1→2) |
> | Deletion | Parallel | Reverse order (2→1→0) |
> | Use case | Stateless apps | Databases, Kafka, ZooKeeper |

---

#### **Question 17**
What is a DaemonSet?

*   A) A background daemon
*   B) A controller ensuring a Pod runs on all (or selected) nodes, typically for node-level operations
*   C) A deprecated feature
*   D) A service type

**Answer: B**
> **Explanation:** DaemonSets run one Pod per node:
> - Automatically adds pods to new nodes
> - Removes pods from deleted nodes
> - Use cases:
>   - Log collectors (Fluentd, Filebeat)
>   - Monitoring agents (Prometheus node exporter)
>   - Network plugins (Calico, Weave)
>   - Storage daemons

#### **Question 18**
What is a Kubernetes Job?

*   A) Employment
*   B) A workload that creates Pods to run a task to completion, then terminates
*   C) A service type
*   D) A deprecated feature

**Answer: B**
> **Explanation:** Jobs for batch processing:
> ```yaml
> apiVersion: batch/v1
> kind: Job
> metadata:
>   name: backup-job
> spec:
>   completions: 1
>   parallelism: 1
>   template:
>     spec:
>       containers:
>       - name: backup
>         image: backup-image
>       restartPolicy: Never
> ```
> - **CronJob**: Schedules Jobs on cron schedule
> - Runs to completion (not continuously)

*   B) An abstraction that defines a logical set of Pods and a policy to access them (stable networking)

*   D) NodePort is internal

#### **Question 21**
What is a Kubernetes Ingress?

*   A) An entrance
*   B) An API object managing external access to services, typically HTTP/HTTPS with routing rules
*   C) A Pod type
*   D) A deprecated feature

**Answer: B**
> **Explanation:** Ingress for HTTP/HTTPS routing:
> ```yaml
> apiVersion: networking.k8s.io/v1
> kind: Ingress
> metadata:
>   name: my-ingress
> spec:
>   rules:
>   - host: api.example.com
>     http:
>       paths:
>       - path: /users
>         pathType: Prefix
>         backend:
>           service:
>             name: users-service
>             port:
>               number: 80
> ```
> Requires an Ingress Controller (NGINX, Traefik, etc.)

### **📌 KUBERNETES - STORAGE** (1 Question)

#### **Question 24**
What is a Kubernetes PersistentVolume (PV)?

*   A) Permanent storage
*   B) A cluster resource representing storage provisioned by an administrator or dynamically
*   C) Pod storage
*   D) A deprecated feature

**Answer: B**
> **Explanation:** Persistent storage in Kubernetes:
> ```
> PersistentVolume (PV)     → Actual storage (admin provisioned)
>         ↑
> PersistentVolumeClaim (PVC) → Request for storage (user request)
>         ↑
> StorageClass              → Dynamic provisioning template
> ```
> - PVs are cluster-wide resources
> - PVCs are namespace-scoped
> - StorageClasses enable dynamic provisioning

### **📌 KUBERNETES - SCALING & HEALTH** (2 Questions)

#### **Question 25**
What are Kubernetes probes (liveness, readiness, startup)?

*   A) Investigation tools
*   B) Health checks determining if containers are alive, ready for traffic, or still starting
*   C) Debugging tools
*   D) Deprecated features

**Answer: B**
> **Explanation:** 
> | Probe | Purpose | Failure Action |
> |-------|---------|----------------|
> | Liveness | Is container running? | Restart container |
> | Readiness | Is container ready for traffic? | Remove from Service endpoints |
> | Startup | Has container started? | Kill and restart |
> 
> Probe types: HTTP GET, TCP Socket, Exec command

#### **Question 26**
What is a Horizontal Pod Autoscaler (HPA)?

*   A) Horizontal scaling
*   B) A controller that automatically scales Pod replicas based on CPU/memory utilization or custom metrics
*   C) A vertical scaler
*   D) A deprecated feature

**Answer: B**
> **Explanation:** HPA automatically scales replicas:
> ```yaml
> apiVersion: autoscaling/v2
> kind: HorizontalPodAutoscaler
> metadata:
>   name: my-app-hpa
> spec:
>   scaleTargetRef:
>     apiVersion: apps/v1
>     kind: Deployment
>     name: my-app
>   minReplicas: 2
>   maxReplicas: 10
>   metrics:
>   - type: Resource
>     resource:
>       name: cpu
>       target:
>         type: Utilization
>         averageUtilization: 70
> ```

### **📌 KUBERNETES - TOOLS & OPERATIONS** (4 Questions)

#### **Question 27**
What is kubectl?

*   A) Kubernetes control
*   B) The command-line tool for interacting with Kubernetes clusters
*   C) A container runtime
*   D) A deprecated tool

**Answer: B**
> **Explanation:** kubectl is the Kubernetes CLI:
> ```bash
> kubectl get pods                    # List pods
> kubectl describe pod <name>         # Pod details
> kubectl logs <pod>                  # View logs
> kubectl exec -it <pod> -- /bin/sh  # Shell into pod
> kubectl apply -f manifest.yaml      # Apply config
> kubectl delete pod <name>           # Delete pod
> kubectl port-forward pod/x 8080:80  # Port forward
> ```

#### **Question 28**
What is the difference between kubectl apply and kubectl create?

*   A) They are identical
*   B) create creates new resources only; apply creates or updates resources declaratively
*   C) apply is deprecated
*   D) create updates resources

**Answer: B**
> **Explanation:** 
> | Command | Creates | Updates | Preferred Use |
> |---------|---------|---------|---------------|
> | `kubectl create` | ✅ | ❌ (fails if exists) | Imperative, one-time |
> | `kubectl apply` | ✅ | ✅ | Declarative, GitOps |
> 
> **Best practice**: Use `apply` for declarative management with version-controlled manifests.

#### **Question 29**
What is Helm in Kubernetes?

*   A) A ship's wheel
*   B) A package manager for Kubernetes that uses charts to define, install, and upgrade applications
*   C) A deprecated tool
*   D) A kubectl plugin

**Answer: B**

> - **Charts**: Packages of Kubernetes resources
> - **Values**: Configuration for customization
> - **Releases**: Installed instances of charts

> helm rollback my-postgres 1
> ```
